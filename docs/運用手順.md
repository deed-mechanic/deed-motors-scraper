# 市場価格データ 自動更新の運用手順

## 仕組み
- 毎日 **0:00（UTC+8）** に、このPCのタスクスケジューラ「DEED MOTORS 市場価格 日次更新」が
  `scripts\run_daily_local.ps1` を実行する（約90分）。
- 取得 → HTML生成 → GitHubへ公開（push）まで自動。GitHub Actionsは遮断（Cloudflare 403）されるため取得には使えない。
- **GitHub側の見張り役**（`.github/workflows/watchdog.yml`）が毎日10:00にデータの古さ（取得完了から14時間超）・
  件数・車種数を確認し、異常ならメールで通知する（前夜の取得が飛んだ場合、その日の朝に届く）。
- 査定ツールの画面は、市場データが2日以上古いと上部に黄色（4日以上は赤）の警告を出す。

## 駆動方式の取得（4WD設定のある車種）
- 一覧ページには駆動方式がほぼ書かれていないため、4WD設定のある車種（`scripts/scraper.py` の
  `_DRIVE_DETAIL_KEYS`）は、広告の詳細ページを開いて駆動方式とハンドル位置を取得する。
- 表記は「Бүх дугуй 4WD」「Урдаа FWD」「Хойноо RWD」。4WD/AWDは4WD、FWD/RWDは2WDとして扱う。
- トヨタ/レクサスは、詳細ページの「Серийн ангилал（型式）」の数字部が5で終わる場合（例: GYL25、AVU65）は
  4WDを優先する（出品者の入力する駆動方式欄は誤りが多いため）。
- 常時4WDの車種（LX / GX / Gクラス / ランドローバー系）は4WD固定。
- 取得結果は広告IDごとに `scripts\.detail_cache.json` に保存し、2回目以降は新規広告だけ詳細ページを開く。
  1晩あたりの新規取得は100分まで（超えた分は翌晩以降）。最初の数晩で保存データが埋まる。
  保存データは消しても自動で作り直される（その晩の所要時間が延びるだけ）。
- 進み具合は、実行ログ末尾の整合チェック `[D] 駆動方式: …不明率` と、
  「詳細ページ: 新規取得N / 保存済みM / 次回へ繰り越しK」で確認できる。
- 一覧のカード名はサイト更新で変わる（過去にCardGridDesktop→CardGridLinkで解析が止まった）。
  広告IDの目印（data-marker）で読むため通常は影響しないが、見出しに件数があるのに0件しか読めない場合は
  「取得失敗」として扱い、前回データを残す（ログに ❌ が出る）。

## 誤ったデータを出さないための検証（顧客への提示額の根拠になるため）
取得のたびに、公開の直前に `scripts/validate_data.py` が自動で検証する。疑わしい車種は「前回の正常データ」に戻して公開し、
結果は「失敗」で記録されるので朝の確認で気づける（詳細は `~/deed-scrape-logs/validation_report.txt`）。

| 区分 | 内容 | 動作 |
|---|---|---|
| E1 | 価格(1〜500)・年式(1990〜2027)・駆動方式の値が不正 | そのレコードを削除 |
| E2 | 取得対象に設定した年式範囲外 | そのレコードを削除 |
| E3 | 広告タイトルのメーカーが車種キーと合わない（別車種の混入） | その車種を差し戻し |
| E4 | 別の車種と中身がほぼ同一（同じ検索結果を複数車種に保存） | 新しい方を差し戻し |
| E5 | 件数が前回から激減（前回10件以上で40%未満） | 差し戻し |
| W | 中央値が前回から35%以上変動（件数が少ない車種も対象）／外れ値／件数の急増／輸入年が生産年より前／2〜5件の車種で最高値が最安値の3倍以上 | 警告（公開はする） |

加えて、取得段階で「/search/ やトップへのリダイレクト」は成功扱いにせず取得失敗にする。
2026-11-24に、専用カテゴリ廃止で `/search/` に飛ばされ、Palisade55件・GLE16件として別車種の検索結果を保存していた事故の再発防止。

ツール画面（査定結果カード）側の注意表示:
- 該当する生産年（±2年）の市場データが無く全年式で算出した場合は「提示に使わないでください」と赤字で明示
- 算出の根拠が2件以下／5件未満のときは注意を表示（2件以下は金額欄にも「⚠要確認」を付ける）
- 候補が5件未満で最高値が最安値の2倍以上のときは「ばらつきが大きい」と表示し、金額欄に「⚠要確認」を付ける
- 「⚠要確認」の金額を「印刷・PDF」「説明シート印刷」ボタンで印刷するときは、先に担当者向けの確認画面を出す（紙の内容は変えない）。
  お客様向けの説明シートには注意は印字されない。「印刷・PDF」は査定画面をそのまま印刷するため注意も印字される。
  ブラウザのメニューや Ctrl+P からの印刷では確認画面は出ないので、ボタンから印刷する
- 市場データが2日以上古いと警告、4日以上で強い警告（従来どおり）

## 毎朝の確認（10秒）
1. 次のファイルを開く: `C:\Users\user\deed-scrape-logs\LAST_STATUS.txt`
   - 「成功」＝OK。「失敗」＝理由が書いてある。
   - 「**実行中**」のまま（朝になっても変わらない）＝強制終了された疑い（PCの電源断・スリープ、タスクの実行時間上限など）。
     ログ（下記）の最後の行を見て、手動で再実行する。
2. または公開ページの「更新」日付が今日（または昨日）になっているか見る。

## 失敗時の自動対処（人手は不要）
- 取得が完了しないと、10分空けて最大2回、取得済みの車種を飛ばして**途中から再開**する。
- 一部の車種だけ取得できない場合は、その車種だけ前回データのまま残して公開する（全体は更新される）。
- 取得件数が極端に少ない場合（既存の3割未満）は、公開せず既存データを保持する。
- Playwrightのブラウザ（Chromium）が合わない場合は、実行前に自動で導入し直す。
- 取得が極端に遅い日（過去に外部サイトの遅延で1ページ30秒かかった）でも、開始から**7時間**で取得を打ち切り、
  取れた分＋前回データで公開する（タスクの実行時間上限は8時間。上限で強制終了されて何も公開されない事態を避ける）。
- 手動実行と定時実行が重なった場合は、後から始めた方が自動で見送る（二重起動防止）。
- 実行後に整合チェック（`scripts/check_consistency.py`）を実行し、結果をログに残す:
  メニューにあるのにデータが無い車種、前回から消えた車種、件数が半分未満に減った車種。
  「前回あった車種が今回0件」の警告がログに出たら、UNEGUI.MN側のURL・レイアウト変更を疑う。
- 古い実行ログ（30日より前）は自動で削除する。

## 手動で今すぐ更新したいとき
PowerShellで次を1回実行（約90分。終了まで閉じない）:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\user\Downloads\deed-motors-scraper-main\scripts\run_daily_local.ps1"
```

実行中の進み具合を見るとき（別のPowerShellで）:

```powershell
Get-Content (Get-ChildItem $env:USERPROFILE\deed-scrape-logs\run_*.log | Sort-Object LastWriteTime | Select-Object -Last 1) -Wait -Tail 20
```

## 症状別の対処
| 症状 | 原因の目安 | 対処 |
|---|---|---|
| LAST_STATUS.txt が数日前のまま | PCが0:00に起動していない／タスクが無効 | PCを夜間に起動しておく。タスクスケジューラで「DEED MOTORS 市場価格 日次更新」が有効か確認し、手動実行する |
| 「Chromiumの確認/導入に失敗」 | ネット接続の問題 | 接続を確認して手動実行 |
| 「サイトに遮断され続け、今回は更新できませんでした」 | CloudflareがこのPCの回線を一時的に遮断（2026-11-24に発生）。一覧が4車種連続で取れた時点で中止し、データ・更新日時は変更しない（終了コード3）。30分おきに自動再開し、7時間の枠内で遮断が解ければ同じ夜に完了する | 数時間〜翌日に解けることが多い。翌晩も続く場合は回線を変えて手動実行（確認画面の突破は行わない） |
| 「スクレイピング失敗」で件数が極端に少ない | このPCの回線もCloudflareに遮断された可能性 | ログで `Just a moment` / 403 を確認。回線を変えて（別のネットワークから）手動実行。続く場合は対策を相談（プロキシ／店舗常設PC） |
| 「git pull失敗」 | このPCのリポジトリに未コミットの変更がある | `git status` で確認し、変更をコミットするか退避してから手動実行 |
| 「push失敗」 | GitHubの認証切れ／ネット | データはコミット済み。ネット/認証を直してから `git push origin main` |
| 特定の車種だけ「市場データなし」 | UNEGUI.MN側のURL（カテゴリ名）変更、または一覧のレイアウト違い | ログの「スラッグ変更の可能性」「カード未検出」警告を確認。URLなら `scripts\scraper.py` の TARGETS の url を修正。ページ自体は開けて掲載もあるのに「カード未検出」なら、`parse_page` が対応していない表示形式（過去に LX 570 のグリッド表示で発生）なので解析処理を修正 |
| 毎朝「実行中」のまま／前夜の更新が無い | PCがスリープ・電源断、またはユーザーがログオフ（タスクは「ログオン中のみ実行」） | 夜間はPCを起動したままログオン状態にしておく。スリープさせない（電源オプション） |

## ファイルの場所
- 実行ログ: `C:\Users\user\deed-scrape-logs\run_日時.log`
- 最新の結果: `C:\Users\user\deed-scrape-logs\LAST_STATUS.txt`
- 途中経過（再開用・自動削除）: `scripts\.scrape_checkpoint.json`
